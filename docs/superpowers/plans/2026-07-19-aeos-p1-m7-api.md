# AEOS P1.M7 — API + SSE + SDK — Implementation Plan

> **Cold-start brief.** Spec §14. Three deliverables: `packages/api`
> (`@aeos/api`, Fastify server the daemon mounts), `packages/sdk`
> (`@aeos/sdk`, typed client + SSE reader), `apps/cli` (`@aeos/cli`, thin
> golden-path client). Branch `feat/aeos-p1-m7-api`. TDD; R1 flips.

## Decisions

- Fastify 5 + `@fastify/swagger` emit OpenAPI 3.1; `openapi.json` is
  committed and drift-tested in CI (same protocol as contracts schemas).
- Validation: zod at the route boundary (contracts schemas are the ABI);
  the swagger doc is derived from route schemas.
- Envelope everywhere: `{ success, data, error, meta }`.
- SDK types: `openapi-typescript` generates
  `packages/sdk/src/generated/openapi-types.ts` from the committed spec
  (offline, committed, drift-tested) — satisfies "generated TS SDK" with
  a thin hand-written fetch client on top. SSE reader implemented on
  fetch streams (no runtime dep).
- Auth: no auth on loopback binds; any non-loopback host requires
  `AEOS_API_TOKEN` bearer auth (spec §14) — enforced at listen time.
- Objectives run in-process through `@aeos/scheduler` with an injectable
  adapter registry (provider-fake in tests; claude/opencode wired by the
  daemon). Supervisor-spawned runner sessions stay M3/M9 territory.
- SSE backfill: events carry their ULID as the SSE `id`; a reconnect with
  `Last-Event-ID` replays newer events from the transcript before going
  live — exactly-once per event id.

### Task 1  `[AEOS-P1.M7.T1]` Server skeleton + envelope + OpenAPI + error mapping
`src/server.ts`, `src/envelope.ts` — health route, typed error → envelope
mapping (including zod 400s), `gen:openapi` script + committed spec +
drift test, loopback/token listen guard.

### Task 2  `[AEOS-P1.M7.T2]` Resource routes
`src/routes/*.ts` — workspaces CRUD, agents CRUD +
`POST /v1/agents/:id/credential-profile` (BYOK switch), objectives
(create + start + status via plan/checkpoints), memory (read tree/file,
search). Integration tests over a temp `AEOS_HOME`.

### Task 3  `[AEOS-P1.M7.T3]` SSE `/v1/events` + backfill
`src/routes/events.ts` — filters (`types`, `agentId`, `sessionId`),
live bridge from the kernel bus, `Last-Event-ID` transcript backfill;
reconnect test proves exactly-once delivery.

### Task 4  `[AEOS-P1.M7.T4]` SDK + CLI golden path
`packages/sdk` (typed client + SSE reader + generated types),
`apps/cli` (`aeos` bin: workspace/agent create, objective start, events
tail, credential switch). Golden-path test: boot server on a random port
→ run CLI commands → objective completes on provider-fake.

## Exit gate
CLI golden path green in CI (in-process server; real daemon socket wiring
demoed in M9).
