# AEOS P2.M5 — PTY Attach + Co-edit Guard Implementation Plan

> **For agentic workers:** task-by-task, in order. Full green bar
> (`pnpm install --frozen-lockfile && pnpm build && pnpm typecheck && pnpm test && pnpm depcruise`)
> before every commit; the completing commit flips that ROADMAP checkbox.

**Goal:** human takeover of a live session via an interactive terminal
(PTY bridged over WebSocket to an xterm.js tab) while the canonical event
stream stays coherent, plus a co-edit guard that pauses the task and asks
for approval when a human edits the agent's work mid-task (spec §9, §14,
§20 OQ1).

**Approved dependencies (Kabeer, 2026-08-25):** `node-pty` (packages/runner),
`@xterm/xterm` + `@xterm/addon-fit` (apps/ade). The WS endpoint additionally
uses `@fastify/websocket` (first-party fastify plugin wrapping `ws`) —
required by the approved T2 scope ("WebSocket attach endpoint"); addition
recorded here and in S09.

## Design decisions

1. **Protocol grows additively, no version bump.** New wire messages
   (`ptyOpen/ptyStarted/ptyInput/ptyResize/ptyOutput/ptyClosed`) ride the
   existing framed socket. An old daemon never sends them; a runner only
   emits PTY traffic after receiving `ptyOpen`, so mixed-version pairs never
   exchange unknown types (D11 discipline).
2. **The PTY hosts an interactive shell** (`$SHELL` ?? `/bin/bash`,
   `TERM=xterm-256color`, cwd = new optional `ptyCwd` RunnerOption), not the
   harness process itself — headless harness CLIs don't re-emit stream-json
   under a TTY. Takeover means working alongside the session in its
   directory; one PTY per session (second `ptyOpen` → `protoError`).
3. **PTY bytes are transport, not taxonomy.** Shell IO does not become
   canonical events (that would pollute transcripts); coherence of the
   canonical stream during takeover IS the T1 accept. A metadata-only log
   (`<sessionDir>/pty.log`: ts/dir/bytes, no content) keeps takeovers
   inspectable without capturing keystrokes.
4. **Release kills the shell.** "Release returns to headless" is enforced:
   releasing closes the WS bridge AND tears down the PTY, so exactly one
   actor remains.
5. **Attach is least-privilege from day one:** allowed only when the
   effective policy tier `execute_commands === 'allow'`; any other tier gets
   a typed WS rejection (default posture = confirm → refused). Confirm-tier
   UX is deferred, noted in S09.
6. **Co-edit target in v0.2 is the agent dir repo** (`worktrees/` layout
   exists but nothing populates it yet). The guard watches whatever git repo
   the daemon hands it — agent dir today, per-objective worktrees when they
   land (ADR-009 records this).

### Task 1: Runner PTY allocation bridged alongside event parsing  `[AEOS-P2.M5.T1]`

**Files:**
- Modify: `packages/runner/src/protocol/messages.ts` — add the six PTY
  message schemas to `WireMessageSchema` (strict, additive).
- Modify: `packages/runner/src/runner/runner.ts` — `RunnerOptions.ptyCwd?: string`;
  lazy PTY lifecycle in the message switch (`ptyOpen` allocates via
  `node-pty`, spawns `$SHELL ?? /bin/bash`, wires `onData` → broadcast
  `ptyOutput` + metadata log line; `ptyInput` → `pty.write`; `ptyResize`;
  child exit or runner close → kill PTY → broadcast `ptyClosed`).
- Modify: `packages/runner/src/protocol/client.ts` — options gain
  `onPtyMessage?`; returned client gains `openPty(cols, rows): Promise<void>`
  (resolves on `ptyStarted`), `sendPtyInput(data)`, `resizePty(cols, rows)`,
  `releasePty()` (sends `ptyClose`… implemented as client-side close request
  message `ptyClose` runner→kill→`ptyClosed`).
- Modify: `packages/runner/src/index.ts` exports as needed.
- Tests: `packages/runner/test/pty.test.ts` (Linux CI):
  - start a Runner with a plain sleeping child, connect client, open PTY,
    write `echo aeos-pty-t1\r` into it, collect `ptyOutput` until the marker
    echoes back;
  - canonical-stream coherence: while the PTY is active, scripted stdout
    lines from the main child arrive as ordered `item.message` events with
    gap-free seq (replay+live);
  - second `ptyOpen` while active → protoError `pty_already_active`;
  - release → shell exits → `ptyClosed` observed;
  - metadata log lines appear in `<sessionDir>/pty.log` without content.

**Steps:** RED pty tests → implement messages + runner + client → green
package suite → full green bar → commit
`feat(runner): PTY allocation bridged alongside event parsing [AEOS-P2.M5.T1]`.

### Task 3: Co-edit detection ADR + guard  `[AEOS-P2.M5.T3]`

**Files:**
- Create: `docs/adr/ADR-009-co-edit-guard.md` — OQ1 resolution: human edits
  in an agent-owned repo mid-task PAUSE the task behind an
  `approval.request` (conservative, lossless); the agent never rebases,
  discards, or force-pushes over foreign changes. Watched repo = the agent
  dir in v0.2 (per-objective worktrees later). Rationale + alternatives
  (ignore / auto-stash / lock) recorded.
- Create: `packages/policy/src/co-edit.ts` — `worktreeStatus(repoPath)`:
  `git status --porcelain` snapshot (sorted lines); `diffStatus(before,
  after): boolean` pure change detector.
- Modify: scheduler loop hook — before advancing to the next task, compare
  snapshots; on change attributable to neither the agent's own checkpointed
  work nor the objective file set → transition task to paused + publish
  `approval.request { reason: 'co_edit', paths }` and wait like other
  approvals (P2.M1 flow answers it).
- Tests: `packages/policy/test/co-edit.test.ts` (fixture git repo): clean
  advance no-op; external file edit between snapshots → detected with paths;
  agent-committed changes (via checkpoint bookkeeping) not flagged.
- Scheduler integration test: induced external edit pauses the fixture
  objective with an approval.request visible through the bus.

**Steps:** RED co-edit tests → implement status/diff → RED integration →
scheduler hook + ADR → full green bar → commit
`feat(policy): co-edit guard + ADR-009 [AEOS-P2.M5.T3]`.
