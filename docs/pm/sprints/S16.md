- 2026-09-26 — P4.M1 container sandbox tier shipped on
  `feat/p4-m1-sandbox`.
  - Tier selection: policy `sandbox: {tier, classes, image, network}`,
    merged workspace → agent → objective.
  - What the container sees: the worktree, its git common dir, the agent's
    profile directory and the harness binary (read-only). Environment
    values are forwarded by variable name only, so they never appear in
    argv.
  - Housekeeping: orphaned containers are reaped on boot, and the tier
    choice is recorded on `route.decided`.
  - The e2e runs on the real daemon with a BYO stand-in `claude`. The
    `implement` task runs inside the container; a host canary outside the
    worktree gives ENOENT and is left byte-identical. The `docs` task, set
    to tier `none` by the same policy, can read the canary (the control
    case).
  - Local `aeos sandbox build` is blocked here by egress policy (403 from
    deb.debian.org). The new CI job `sandbox-image` builds the image and
    runs the e2e on it.
- 2026-09-26 — PR #127 (P4.M1): the `supervisor-pty` teardown race came
  back in CI. The root cause was deeper than first fixed: a runner stays
  alive after its child ends, because it serves re-adoption. The test now
  terminates the runner it owns and waits for the pid to exit.
  - Process slip: one intermediate fix was pushed with a failing local
    test. A `for … | grep` loop masked the exit status. The follow-up
    commit fixed it before CI finished. Rule: check pass/fail explicitly,
    never through a pipeline's last command.

- 2026-09-26 — P4.M3 deploy targets shipped on `feat/p4-m3-deploy`.
  - Found: a token-protected (remote) daemon could not serve its own web UI
    at all. The token hook covered the static shell, and the ADE had no
    token support. Fixed: the gate is scoped to `/v1`, uses a
    constant-time compare, and the ADE gets a sign-in form (Playwright
    T10).

    would kill detached runners on every daemon restart. Set
    `KillMode=process` / `AbandonProcessGroup`.
  - Found (tracked next): objective-run sessions log
    `TranscriptRoutingError` for every event, because they have no session
    record, so there is no transcript (spec §7).
